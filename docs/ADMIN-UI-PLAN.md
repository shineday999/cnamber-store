# 後台 UI/UX 整併計畫（進度追蹤）

> 目標：功能位置收攏、版面緊湊、**所有參數集中在「设置」一個區域**，頁面不再又長又鬆。
> 範圍：`src/layouts/AdminLayout.astro` 與 `src/pages/admin/**`。前台、資料表、API 邏輯不在此計畫內
> （商品資料與價格的後台重寫另見 `docs/ADMIN-PRODUCTS-PLAN.md`）。

## 協作規則（多人請務必遵守）

1. **開工前先認領**：在下方步驟表填上「負責人」，單獨 commit 並 push，避免撞工。
2. **一個步驟一個分支、一個 PR**：分支 `feat/admin-ui-<步驟>`，例如 `feat/admin-ui-4-products`。
3. **做完同一個 commit 內更新本文件**：狀態改 ✅、填日期，並在文末「更新紀錄」加一行（寫清楚動了哪些檔案、有什麼坑）。
4. commit 格式：`feat(admin): <說明>`；合併前跑 `pnpm check && pnpm build`（pre-commit 會跑 eslint 與 prettier）。
5. **部署**：合併到 `main` 會自動觸發 Deploy workflow。**CI 政策（owner 決定）**：`lint`、`build-check` 等 PR 檢查失敗
   不擋合併與部署；但 Deploy 自己的 build（`check` + `build` + `test`）失敗時 Cloudflare 不會部署，必須先修。
6. **資料庫遷移**要先於程式部署套用，所以遷移必須向後相容舊版程式（先加欄位／資料，之後再清舊的）。
7. 同一個頁面不要兩人同時改；要改別人認領中的步驟，先在該列留言並確認。

## 導覽架構（`AdminLayout.astro` 的 `NAV`）

導覽依**網址路徑**自動判斷所在群組，頁面傳的 `active` 已不使用（保留只為相容）。新增後台頁面時，到 `NAV` 登記路徑即可。

| 群組 | 路徑                                                                                         | 子頁籤                                   |
| ---- | -------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 概览 | `/admin`                                                                                     | —                                        |
| 商品 | `/admin/products/**`                                                                         | —（列表、新增、編輯）                    |
| 订单 | `/admin/orders/**`                                                                           | —                                        |
| 内容 | `/admin/posts/**`、`/admin/reviews`                                                          | 文章、评论                               |
| 设置 | `/admin/settings`、`/admin/banners`、`/admin/category-images`、`/admin/rates`、`/admin/faqs` | 站点、首页横幅、分类图片、汇率、常见问题 |

**規則：站台層級的參數／設定一律放「设置」群組**（站名、主題、橫幅、分類、匯率、常見問題…），
商品、訂單、文章、評論這類「一筆一筆的資料」才放在各自的群組。

## 版面慣例（新頁面與改版請沿用）

- 頁首：`<AdminLayout title="…">`；頁面專屬操作（例如「返回列表」）放 `slot="actions"`，會顯示在標題右側。
- 卡片：`rounded-card border border-text-muted/20 bg-bg-card p-4`（不要超過 `p-5`）；區塊間距 `gap-4`／`space-y-4`；
  卡片標題 `h2 font-serif text-lg`。
- 表格：外層 `overflow-x-auto`；儲存格 `px-3 py-2`；表頭 `text-xs`。列表多的頁面用**篩選膠囊鈕 + 網址參數**
  （例：`?status=pending`），參數在伺服器端用白名單驗證。
- 表單：主要儲存鈕固定在底部（`sticky bottom-0` 的儲存列）或卡片內全寬；次要的表單收進原生 `<details>`。
- `<textarea>` 的內容必須緊貼標籤寫（`<textarea …>{value}</textarea>`），中間換行縮排會被存進資料庫。
- HTML 表單要發 PATCH／DELETE 時用隱藏欄位 `_method` 覆寫；**PATCH 表單必須帶齊該筆資料所有欄位**，
  缺的欄位會被當成預設值寫回（首頁橫幅曾因此在換手機版圖片時被清空說明、排序歸零）。
- 後台新增的文字目前直接寫簡體中文（後台只有簡體介面）；既有 i18n key 沿用、不要刪除。
- `AdminLayout.astro` 底部有一段 `<style is:global>` 暫時縮小 `h2.text-xl` 與 `space-y-6/8` 的間距，
  是各頁還沒逐頁精簡前的過渡做法；全部步驟完成後可以移除。
- 用詞統一（後台）：一律用「商品」（不用「产品」）、「规格」（不用「变体」）、狀態「草稿／上架／已下架」（不用「归档」）。前台文案不在此限。新增後台文字請沿用。

- 商品編輯頁只做版面精簡；`docs/ADMIN-PRODUCTS-PLAN.md` 的 4.4 之後若重寫 `[id].astro`，請沿用本頁的版型與固定儲存列。翻譯內容過去每存一次可能前後多出換行縮排，已修正寫入，但資料庫中已存在的內容不會自動清理。
