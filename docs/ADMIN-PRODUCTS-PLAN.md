# 後台產品管理重寫計畫（進度追蹤）

> 目標：後台「產品」整個重寫，讓一次就能建立完整商品（基本資料、多語翻譯、變體、多幣別價格、圖片），不再需要手動改 seed.sql。
> 資料前提：目前網站的商品都是測試資料，也還沒對外公告，可以直接刪改。因此**不需要相容舊資料、不做新舊並存**，直接改寫原路徑 `/admin/products`。
> 驗收標準：清空假資料後，只用新後台建立一個含 4 種語言、2 個變體、3 種幣別的商品，前台顯示正確；前台商品列表、詳情、購物車、推薦測驗、預訂流程都正常。

## 協作規則（多人請務必遵守）

1. **開工前先認領**：在下方表格把「負責人」填上自己的名字，單獨 commit 並 push，避免撞工。
2. **使用整合分支**：先由 Lead 建立 `feat/admin-products`。每個步驟從它分出 `feat/admin-products-<步驟編號>`（例如 `feat/admin-products-1-3`），PR 也合併回整合分支；階段 6 驗收通過後才一次合併進 main。
   原因：資料表變更會連動前台查詢，若中途就部署 main，前台可能壞掉。
3. **做完同一個 commit 內更新本文件**：狀態改 ✅、填日期，並在文末「更新紀錄」加一行。
4. commit 格式：`feat(admin-products): 1.3 add repo list/get`。
5. 合併前跑：`pnpm check && pnpm build`。部署由 GitHub Actions 的 deploy workflow 手動觸發；整合分支在階段 6 之前不部署到正式環境。
6. **Migration 編號先認領**：目前最後一個是 `0013`。需要新增 migration 的步驟，已在「內容」欄預留編號（0014 起），不要自己另取號碼。因為資料是假的，可以重建資料表或清資料，但**不要修改已套用過的舊 migration 檔**（D1 不會重跑），一律用新的 migration 處理。會讓前台壞掉的刪除類動作（例如 `DROP COLUMN`）統一放到階段 6。
7. **Migration 先在本機驗證**（`wrangler d1 migrations apply --local`），正式環境由 Lead 在階段 6 統一套用。
8. **契約先於實作**：`src/lib/schemas/product.ts`（階段 0）合併前，其他階段只能做原型；之後要改 schema 必須開 PR 並在更新紀錄註明，讓所有人知道。
9. **i18n 鍵統一用 `admin.products_v2.*` 前綴**，只新增、不改舊的 `admin.products_*`（階段 6 再統一刪除舊鍵，避免多人同時改同一個 JSON 而衝突）；後台文案維持簡體（zh-Hans），與現有後台一致。
10. **前台只在指定步驟才能動**：除了 1.8（前台查詢調整），不改前台頁面、`src/styles/mobile.css`、`quiz.ts` 既有行為；需要動時先在「已知問題」記錄並找 Lead 確認。
11. **編輯頁避免多人改同一個檔**：`[id].astro` 只在 4.4 由一個人完成骨架，之後各頁籤各自是獨立元件檔（`src/components/admin/products/tabs/`），每人只改自己認領的那一個。

狀態符號：⬜ 未開始　🟡 進行中　✅ 完成

## 已知問題

- `lib/db.ts` 的 `Product` 型別缺少 `image_url`、`tags`、`faq`，但 migration 0004、0006、0008 已加上這些欄位（0.3 處理）
- 價格有兩個來源：`product_variants.price_base` 與 `product_prices`；前台是否直接讀 `price_base` 尚未確認（0.1 處理）
- 後台變體與價格目前只能靠 `seed.sql` 新增（i18n 寫著「請通過 seed.sql 添加」），階段 3、4 處理
- tags 是自由文字，推薦測驗用 token 比對，打錯字就不會匹配（階段 5 處理）
- 分類 `jewelry` / `incense` 寫死在表單與 i18n，沒有資料表（1.1 處理）
- migration 清單從 0001 跳到 0003，缺 0002（0.5 處理）
- migration 0009、0011 是對測試商品與文章寫入 FAQ；重置商品資料後，在新環境重建 DB 時這兩支 migration 會對不到商品（0.1 一併確認影響，必要時 1.7 補上新的示範 FAQ）
- 刪除商品會連帶刪除變體、翻譯、評論，沒有軟刪除；目前資料是測試資料可接受，上線前處理（後續階段 11）
- 匯率寫死在 `lib/format.ts`，不在本次範圍（後續階段 10）
- 前台商品圖全部讀變體 `image_urls`（products/index、quiz/result、cart、HomeContent、products/[slug]），`products.image_url` 只有後台使用；封面若不同步，後台上傳的封面不會出現在前台（見決策「封面圖」）
